Node.js به زبان ساده: فرار جاوااسکریپت از مرورگر

Node.js واقعاً چیست (یک ران‌تایم است، نه زبان)، event loop چطور با یک تِرِد به هزاران کاربر سرویس می‌دهد، کجا از PHP و Python و Java بهتر است و کجا می‌بازد — با چیت‌شیت عملی.

English version of this post ❯

Node.js پل من از دنیای اندروید به بک‌اند بود. در بوتکامپ BreakPoint بک‌اند پروژه‌مان را با Node.js روی معماری ماژولار و لایه‌ای ساختیم و بعداً پلتفرم چت هوش مصنوعی خودم هم کل API‌اش روی آن اجرا می‌شد. با پیش‌زمینه‌ی Javaِ تایپ‌دار، اولین واکنشم «پس کلاس‌ها کجاست؟!» بود و دومی: «صبر کن، این چیز هزاران کاربر را روی یک ترد سرویس می‌کند؟!» این پست همان توضیحی است که برایم همه‌چیز را جا انداخت.

خلاصه برای عجول‌ها — Node.js نه زبان است و نه فریم‌ورک؛ یک ران‌تایم است: موتور V8 کروم + یک لایه‌ی C++ که اجازه می‌دهد جاوااسکریپت بیرون از مرورگر اجرا شود. ابرقدرتش I/O غیرمسدودکننده روی event loop است — برای API و اپ‌های ریل‌تایم فوق‌العاده، ابزار اشتباه برای محاسبات سنگین CPU.

Node.js واقعاً چیست؟

سه اصلاح برای سردرگمی رایج:

  1. زبان نیست. زبان، جاوااسکریپت است (یا TypeScript).
  2. فریم‌ورک نیست — Express و NestJS فریم‌ورک‌هایی هستند که روی آن اجرا می‌شوند.
  3. ران‌تایم است: در ۲۰۰۹ رایان دال موتور متن‌باز V8 کروم را برداشت، آن را با libuv (کتابخانه‌ی event loop و I/O ناهمگام) و بایندینگ‌های فایل/شبکه بسته‌بندی کرد — و ناگهان جاوااسکریپت می‌توانست روی سرور اجرا شود، فایل بخواند، سوکت باز کند و با دیتابیس حرف بزند.
snippet.bash
$ node -v
v22.14.0

قبل از Node، جاوااسکریپت فقط داخل مرورگرها زندگی می‌کرد. بعد از Node، همان زبان هم تب مرورگر را اجرا می‌کرد هم سروری را که به آن جواب می‌داد — ایده‌ی «یک زبان همه‌جا» که توسعه‌ی وب را از پایه عوض کرد.

Event loop: یک گارسون، یک رستوران کامل

مدل ذهنی‌ای که Node را جا می‌اندازد:

  • سرورهای کلاسیک (به سبک PHP/Java) مثل رستورانی‌اند که برای هر مشتری یک گارسون استخدام می‌کنند. یک سفارش کند (کوئری دیتابیس، خواندن فایل)، یک کارگر کامل را پارک می‌کند. با ۱۰۰۰ مشتری، ۱۰۰۰ گارسون لازم است — تردها گران‌اند.
  • Node.js یک گارسون نابغه استخدام می‌کند که هیچ‌وقت بی‌حرکت نمی‌ایستد: سفارش تو را می‌گیرد، به آشپزخانه می‌دهد (سیستم‌عامل و I/O ناهمگام) و فوراً سراغ میز بعدی می‌رود. وقتی آشپزخانه زنگ می‌زند (یک callback/promise آماده می‌شود)، نتیجه را می‌آورد.

این همان event loop است: یک تردِ تنها که رویدادها را پردازش می‌کند در حالی که هر عملیات کند به‌صورت ناهمگام در پس‌زمینه انجام می‌شود. به همین دلیل Node روی یک هسته هزار اتصال هم‌زمان را نگه می‌دارد — و به همین دلیل یک محاسبه‌ی سنگین CPU کل رستوران را قفل می‌کند: گارسون خودش آشپزی می‌کند، پس یک حلقه‌ی ریاضی ۱۰ ثانیه‌ای همه را فریز می‌کند. (Worker Threadها دقیقاً برای همین فرار ساخته شده‌اند.)

snippet.js
// غیرمسدودکننده: سرور در حین خواندن فایل، به بقیه جواب می‌دهد
import { readFile } from "node:fs/promises";

app.get("/report", async (req, res) => {
  const data = await readFile("report.json", "utf8"); // گارسون منتظر نمی‌ماند
  res.json(JSON.parse(data));
});

واقعاً برای چه استفاده می‌شود؟

  • APIهای REST/GraphQL — کاربرد کلاسیک: اندپوینت‌های JSON برای وب و موبایل (بک‌اند پلتفرم چت AI من دقیقاً همین است).
  • قابلیت‌های ریل‌تایم — WebSocket، چت زنده، استریم موقعیت راننده. event loop برای هزاران اتصال باز ساخته شده.
  • ابزارهای بیلد — طنز ماجرای وب مدرن: همه‌ی فریم‌ورک‌های فرانت‌اند (React، Vue، Next.js) با ابزارهای Node بیلد و سرو می‌شوند (Vite، npm).
  • ابزارهای CLI و خودکارسازی — اسکریپت‌های دیپلوی، ربات‌ها، اسکرپرها.
  • میکروسرویس و serverless — توابع کوچک با بوت میلی‌ثانیه‌ای جور طبیعی‌اند.

الگوی صادقانه‌ای که می‌بینم: اگر اپ تو بیشتر منتظر می‌ماند (دیتابیس، API، سوکت)، مدل Node فوق‌العاده است. اگر بیشتر محاسبه می‌کند (انکود ویدیو، ML، ریاضیات سنگین)، زبانی را انتخاب کن که برای همان ساخته شده — یا آن بخش را به یک سرویس جدا بده.

دنیای npm

Node همراه خودش npm را می‌آورد؛ بزرگ‌ترین مخزن نرم‌افزاری تاریخ (~۲ میلیون پکیج — پست جاوااسکریپت من درباره‌اش نوشته). صادقانه: نصف بهره‌وری Node همان npm install و کتابخانه‌ی آزمون‌پس‌داده برای همه‌چیز است، و نصف دیگرش نوشتن اسکریپت‌های package.json است تا دیپلوی یک دستوری شود.

مزایا و معایب، صادقانه

می‌برد:

  • یک زبان در کل استک: تایپ‌های مشترک، اعتبارسنجی مشترک، یک استخدام.
  • پرفورمنس استثنایی I/O به آن سادگی؛ بوت میلی‌ثانیه‌ای (عالی برای serverless و کانتینر).
  • غنی‌ترین اکوسیستم؛ هر چیزی یک install فاصله دارد.
  • رفیق طبیبی فریم‌ورک‌های فرانت: Next.js و Nuxt و Vite همه روی Node زندگی می‌کنند.

می‌بازد:

  • کارهای سنگین CPU حلقه را قفل می‌کنند — انکود ویدیو و inference مدل‌های یادگیری ماشین مال سرویس دیگری است.
  • زخم قدیمی eraی callback: کدهای قدیمی مثل هرم می‌خوانند؛ async/await مدرن کد را درست کرد، نه آموزش‌های قدیمی را.
  • تلاطم: وابستگی‌ها و فریم‌ورک‌ها سریع عوض می‌شوند (همان قصه‌ی کلی دنیای JS).
  • برای سیستم‌های سازمانی بزرگ، Java/C# هنوز ابزارهای بلندمدت قوی‌تر و انضباط تایپی بیشتری دارند (TypeScript خیلی از این فاصله را پر می‌کند).

چقدر محبوب است؟

  • Netflix و PayPal و LinkedIn و Uber به‌شهرت سرویس‌های حیاتی‌شان را به Node بردند — PayPal ۳۵٪ پاسخ‌دهی سریع‌تر و Netflix کاهش عظیم زمان بوت را بعد از مهاجرت گزارش کرد.
  • npm رتبه یک مخازن پکیج دنیاست — هیچ رقیبی نزدیک نیست.
  • بیشترِ ابزارهای ابری مدرن (CLIها، ران‌تایم‌های serverless، dev serverها) با Node نوشته شده‌اند.
  • کنار انحصار فرانت‌اند، جاوااسکریپت + Node بزرگ‌ترین اکوسیستم توسعه‌دهنده‌ی تاریخ را می‌سازند.

چیت‌شیت — دستوراتی که مهم‌اند

snippet.bash
node -v                       # چک نسخه (LTS = اعداد زوج)
npm init -y                   # ساخت package.json
npm install express           # اضافه‌کردن وابستگی
npm run dev                   # اجرای یک اسکریپت از package.json
npx create-next-app@latest    # اجرای پکیج بدون نصب سراسری

node --watch server.js        # ری‌استارت خودکار بعد از تغییر (داخلی!)
node -e "console.log(process.version)"
snippet.js
// مینیمال‌ترین HTTP سرور — بدون هیچ وابستگی
import { createServer } from "node:http";

createServer((req, res) => {
  res.end("Hello from Node!");
}).listen(3000, () => console.log("Listening on :3000"));

چرا مهم است

Node.js دیوار بین مرورگر و سرور را شکست. یک زبان، یک مدل ذهنی، از دکمه‌ی روی صفحه تا دیتابیسی که پشت آن است — و یک event loop که جاوااسکریپتِ مسخره‌شده را به یکی از پراستقرارترین تکنولوژی‌های سروری زمین تبدیل کرد. اگر جاوااسکریپتِ فرانت بلدی، بک‌اند نصفه‌کامه آشناست: npm init بزن و ببین.

نسخه‌ها و بنچمارک‌ها عوض می‌شوند؛ اعداد روز را از nodejs.org و مخزن npm چک کن.
