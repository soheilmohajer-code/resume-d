26:Tacc,<p>I have shipped production agents twice: once as a nest of n8n workflows, once
as a Python service. Both solved the problem. Neither was the right tool
everywhere. This is the comparison I keep getting asked for.</p>
<h2 id="iteration-speed">Iteration speed</h2><p>n8n wins the first week. Dragging nodes, wiring credentials, hitting execute
and watching data flow through each step is genuinely the fastest way to
explore an API and prototype a pipeline. Writing the same thing in code means
you rebuild the observability that n8n gives you for free.</p>
<p>Around week two the curve crosses. Once logic needs conditions on conditions,
loops over paginated results, or error branches that themselves branch, the
canvas becomes a diagram you <em>read</em> instead of code you <em>refactor</em>.</p>
<h2 id="debugging-and-versioning">Debugging and versioning</h2><ul>
<li><strong>n8n:</strong> executions log is excellent for &quot;what happened&quot;, weak for &quot;why&quot;.
Versioning is export/import JSON — diffs are unreadable and merges are
manual. One active workflow edits by anyone is a production risk.</li>
<li><strong>Code:</strong> stack traces, tests, <code>git bisect</code>, code review. You pay for it
with setup: logging, retries and a dashboard are yours to build.</li>
</ul>
<h2 id="cost-model">Cost model</h2><p>n8n&#39;s pricing is per workflow execution, not per complexity. A chatty agent
that calls five sub-workflows per user message multiplies fast. Code-first
agents cost compute plus tokens — predictable, and batching is under your
control.</p>
<h2 id="the-hybrid-i-now-default-to">The hybrid I now default to</h2><div class="term" dir="ltr"><div class="term-bar"><span class="d d1"></span><span class="d d2"></span><span class="d d3"></span><span class="file">architecture.txt</span><button type="button" class="copy" data-copy>COPY</button></div><pre class="shiki vitesse-dark" style="background-color:#121212;color:#dbd7caee" tabindex="0"><code><span class="line"><span>trigger + happy path  →  n8n (speed, UI, credentials)</span></span>
<span class="line"><span>hard logic + loops    →  Python service (tests, git, cost control)</span></span>
<span class="line"><span>LLM calls             →  behind one shared service either way</span></span></code></pre></div><p>Rules of thumb that have held up:</p>
<ul>
<li>If a human needs to <em>see</em> the pipeline (ops, content, research digests), n8n.</li>
<li>If a computer needs to <em>verify</em> it (money, scheduling, parsing), code.</li>
<li>Never let an LLM call live inside a loop you cannot cancel.</li>
</ul>
<p>Low-code is a tool, not a identity. The winners are the teams honest about
which parts of their pipeline are prototypes and which are contracts.</p>
