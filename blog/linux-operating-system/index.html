Linux Explained: What It Is, Why People Love It, and Where It Loses

What Linux actually is (kernel vs distro), how it differs from Windows and macOS, the honest pros and cons, and why it quietly runs most of the internet, all supercomputers and your phone.

DATE: Oct 29, 2026READ: ~7 MINAUTHOR: SOHEIL MOHAJER

My first serious contact with Linux wasn't on a desktop — it was on a VPS. When I started self-hosting my automation stack (the same journey from my Docker guide), the server handed to me ran Ubuntu, and there was no Start menu, no installer wizard — just a black terminal and a blinking cursor. It looked hostile. Six months later, it had become the environment I trust most.

This post is the explanation I wish I'd read on day one: what Linux actually is (the word is used for at least three different things), how it really differs from Windows and macOS, an honest list of where it wins and where it loses, and the surprising answer to "how popular is it, really?"

TL;DR — Linux is a free, open-source kernel that anyone can build an operating system around. It dominates servers, supercomputers, Android phones and the cloud, struggles on the consumer desktop (gaming and industry software), and rewards the effort with control nothing else offers.

What Linux actually is

The first surprise: Linux is not an operating system. Strictly speaking, Linux is a kernel — the core program that talks to your hardware (CPU, memory, disk, network) and lets software run. What people call "Linux" in daily conversation is almost always a distribution (distro): a complete operating system assembled from the Linux kernel plus GNU tools, a desktop environment, a package manager and thousands of applications.

That's the second surprise: there is no single Linux. Anyone can take the kernel and build their own OS around it, and people have — thousands of times. Ubuntu, Debian, Fedora, Arch, Mint, Red Hat… they are all "Linux", yet they feel different, the way two cars with the same engine can be completely different vehicles.

And the third: it's free and open source. Not "free trial" free — the source code is public, licensed so that anyone can read it, modify it, redistribute it, and even sell their version. No license activation, no account requirement, no telemetry you can't turn off.

snippet.bash
$ uname -a
Linux vps 6.12.4-generic #1 SMP PREEMPT_DYNAMIC x86_64 GNU/Linux

For the pedants: what most of us run is technically GNU/Linux — the GNU project supplied the compilers, shell and core utilities that make the kernel usable. The naming debate is 30 years old; both camps have a point.

How it differs from Windows and macOS

Windows macOS Linux
Kernel Closed (NT) Closed (XNU/Darwin, partly open) Open (Linux)
Price Paid (bundled) Bundled with hardware Free
Source code Secret Partly open Fully open
Installing software Download .exe from anywhere, or Store App Store + .dmg Central package manager from the distro
Customization Themes, mostly Almost none From fonts to the entire desktop
Who decides updates Microsoft Apple You
Runs on Any PC, best on x86 Apple hardware only Almost anything with a CPU

The deepest difference isn't in the table though — it's the philosophy:

  • Windows is designed for the masses: hardware vendors decide, you click through wizards, the system hides its internals. Great when it works; a black box when it doesn't.
  • macOS is designed for a curated experience: Apple controls hardware and software, so everything fits — as long as you stay inside the garden.
  • Linux is designed for control. Nothing is hidden from you. Every config is a text file you can read and change. If you want to know what runs at boot, you look; if you want to replace the desktop, the shell, even the kernel itself — you can.

Package managers deserve a special mention because they change how you think about software. On Windows, installing an app means visiting a website, downloading an installer, and hoping it's not bundled with junk. On Linux:

snippet.bash
sudo apt install gimp        # Debian/Ubuntu family
sudo dnf install gimp        # Fedora family
sudo pacman -S gimp          # Arch family

One command, from a vetted repository, with automatic updates for all software on the system — the App Store idea, twenty years older and applied to everything.

Where Linux wins

  • Free, truly. No license, no activation, no subscription. Install it on one machine or a thousand.
  • Performance and longevity. A lightweight distro turns a 15-year-old laptop into a usable machine. The same OS scales from a router to the world's biggest servers.
  • Stability. Servers routinely measure uptime in years. There's a reason "it's been up for 400 days" is a Linux brag.
  • Security model. Open code that thousands of eyes review, strict user/permission separation, and a malware landscape that is tiny compared to Windows (smaller user base on desktop, and central repos instead of random installers).
  • Privacy. No account required, no telemetry you can't disable, no ads in the start menu.
  • The terminal. Once you learn it, the shell is a superpower — every task scriptable, every server reachable, every fix a copy-paste away.
  • The ecosystem for developers. Native package managers, the same environment as your production servers, and every language and tool installed with one command.

Where Linux loses (the honest part)

  • Industry software doesn't exist there. No native Adobe Photoshop / Premiere, no native Microsoft Office, no SolidWorks. Workarounds exist (web versions, Wine/VMs), but if your livelihood depends on one of these, that's the dealbreaker.
  • Gaming is better but not equal. Thanks to Valve's Proton, the Steam Deck runs Windows games on Linux impressively well — most games with anti-cheat or DRM still refuse, though. Check areweanticheatyet.com before switching for gaming.
  • Hardware quirks. Most hardware "just works" today, but some Wi-Fi chips, printers and NVIDIA GPUs still need extra drivers or patience. Check compatibility before installing on laptops.
  • Fragmentation. Thousands of distros, several package managers, docs that say "on Debian do X, on Arch do Y". Freedom has a coordination cost.
  • The learning curve is real. You can use Ubuntu like Windows, but the moment something breaks, the answers live in the terminal. That's a feature for some of us and a wall for others.
  • Help is community-based. No Microsoft support line; you get forums, wikis and Discord servers — usually excellent, occasionally humbling.

How popular is it, really?

On the desktop, modest: around 4% of computers (statcounter, 2026) — but that number hides where Linux actually lives:

  • Supercomputers: 100%. Every single machine in the TOP500 list runs Linux. Not most — all of them.
  • Servers and the cloud: dominant. The majority of web servers, and roughly 90% of public cloud workloads, run on Linux.
  • Android: ~3 billion devices. Android is built on the Linux kernel — it's the most used "Linux" on Earth, it just doesn't wear the name.
  • Everything embedded. Routers, smart TVs, cars, Raspberry Pis, satellites, in-flight entertainment… Linux is the default OS of things that aren't computers.
  • Windows runs Linux now. WSL (Windows Subsystem for Linux) puts a real Linux environment inside Windows — Microsoft's quiet concession to where development actually happens.
  • Steam Deck. Valve's handheld runs SteamOS, a Linux distro — the biggest consumer-desktop push in years.

So the fair summary: Linux lost the desktop war and won everything else.

Which distro should you try?

If you want… Try
"Just works", closest to Windows habits Linux Mint or Ubuntu
Bleeding edge, learn Linux properly Fedora (polished) or Arch (advanced)
Reviving old hardware Linux Mint XFCE or Lubuntu
Servers / what the industry runs Ubuntu Server LTS or Debian

The safe first step isn't even installing: most distros run live from a USB stick, so you can boot and poke around without touching your disk.

Cheat sheet — the commands that unlock everything

snippet.bash
uname -a                      # kernel + system info
sudo apt update && sudo apt upgrade   # update everything (Debian/Ubuntu)
ls -lah                       # list files, human-readable
cd /etc                       # change directory
cat file.conf                 # print a file
grep -r "error" /var/log      # search inside files
ps aux | grep nginx           # find a process
sudo systemctl status nginx   # service status (start/stop/restart)
df -h                         # disk usage
free -h                       # memory usage
man ls                        # the manual for any command
chmod +x script.sh            # make a file executable

Why it matters

Linux is proof that a community of volunteers can out-engineer the richest companies on Earth — and give the result away. Whether or not you ever daily-drive it, understanding it makes you better at everything else: your phone runs it, your servers run it, the internet runs it. Start with a live USB, break things in a virtual machine, and let the terminal grow on you.

Stats reflect late-2026 figures (statcounter, TOP500, cloud provider reports); they move, so check current numbers before quoting them.
