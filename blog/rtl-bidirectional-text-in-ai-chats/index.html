RTL Survival Guide: Fixing Bidirectional Text in AI Chat UIs

Why mixing Persian and English breaks in ChatGPT-style UIs, how first-strong detection fails on streamed responses, and the MutationObserver approach shipped in ParsiChat Fixer.

DATE: Oct 2, 2026READ: ~2 MINAUTHOR: SOHEIL MOHAJER
$ bidi detect --first-strongRTL/LTR: RESOLVED[OK]

If you have ever pasted a Persian sentence with an English variable name into a chat UI and watched the punctuation teleport to the wrong side, you have met the Unicode Bidirectional Algorithm. This post is the field guide I wish I had before building ParsiChat Fixer.

Why "just set dir=rtl" is not enough

The dir attribute sets the base direction of a block. Inside that block, the Unicode Bidi Algorithm reorders runs of opposite direction. Most chat UIs render assistant messages as one block with a guessed base direction, so a reply that starts with Sure, here is the code: gets dir=ltr — and every Persian sentence inside it renders with scrambled punctuation and wrong-side numbers.

First-strong detection, and how streaming breaks it

The HTML default is exactly what the spec calls first-strong: the base direction comes from the first strong character. That works for complete messages — and fails beautifully for streamed tokens:

  • Token 1: The → block becomes LTR.
  • Token 2: متغیر — now the paragraph mixes directions with the wrong base.
  • The DOM is patched in place, so the initial decision is never revisited.

The fix: per-block detection plus a patient observer

What actually worked in ParsiChat Fixer:

  1. Split each message into paragraph-level blocks and decide direction per block, not per message.
  2. First-strong character with a twist: if the first line has no strong character, fall back to a Persian/Latin character ratio for the block.
  3. Watch the DOM with a MutationObserver and debounced re-evaluation, so streamed replies settle only after a quiet period — evaluating on every token melts the main thread.
  4. Wrap embedded code spans with dir=ltr + unicode-bidi: embed so identifiers keep their shape inside RTL paragraphs.
direction.js
function blockDirection(text) {
  const first = text.match(/\p{L}/u);          // first letter, any script
  if (first && /[\u0600-\u06FF]/.test(first[0])) return "rtl";
  const fa = (text.match(/[\u0600-\u06FF]/g) ?? []).length;
  const lat = (text.match(/[A-Za-z]/g) ?? []).length;
  return fa / (fa + lat || 1) > 0.35 ? "rtl" : "ltr";
}

Bonus round: digits, mirrors, and invisible marks

  • Use unicode-bidi: plaintext on user-generated single-line inputs; it does first-strong per element for free.
  • Persian digits (۰-۹) are weakly directional — a Latin-context number in an RTL sentence is where "۳.5MB vs 3.5MB" bugs are born.
  • Test with the string נסה قلم ABC.123 پایان — if that renders sanely, you are 90% done.

Bidirectional text is not exotic: it is the daily reality of hundreds of millions of users typing into UIs designed left-to-right. Treat direction as content, not chrome.
