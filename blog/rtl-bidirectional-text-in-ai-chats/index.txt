14:T1cde,<p>If you have ever pasted a Persian sentence with an English variable name into
a chat UI and watched the punctuation teleport to the wrong side, you have
met the Unicode Bidirectional Algorithm. This post is the field guide I wish
I had before building ParsiChat Fixer.</p>
<h2 id="why-quotjust-set-dirrtlquot-is-not-enough">Why &quot;just set dir=rtl&quot; is not enough</h2><p>The <code>dir</code> attribute sets the <em>base direction</em> of a block. Inside that block,
the Unicode Bidi Algorithm reorders runs of opposite direction. Most chat
UIs render assistant messages as <strong>one block with a guessed base
direction</strong>, so a reply that starts with <code>Sure, here is the code:</code> gets
<code>dir=ltr</code> — and every Persian sentence inside it renders with scrambled
punctuation and wrong-side numbers.</p>
<h2 id="first-strong-detection-and-how-streaming-breaks-it">First-strong detection, and how streaming breaks it</h2><p>The HTML default is exactly what the spec calls <em>first-strong</em>: the base
direction comes from the first strong character. That works for complete
messages — and fails beautifully for streamed tokens:</p>
<ul>
<li>Token 1: <code>The</code> → block becomes LTR.</li>
<li>Token 2: <code>متغیر</code> — now the paragraph mixes directions with the wrong base.</li>
<li>The DOM is patched in place, so the initial decision is never revisited.</li>
</ul>
<h2 id="the-fix-per-block-detection-plus-a-patient-observer">The fix: per-block detection plus a patient observer</h2><p>What actually worked in ParsiChat Fixer:</p>
<ol>
<li>Split each message into <em>paragraph-level blocks</em> and decide direction per
block, not per message.</li>
<li>First-strong character with a twist: if the first line has no strong
character, fall back to a Persian/Latin character <strong>ratio</strong> for the block.</li>
<li>Watch the DOM with a <code>MutationObserver</code> and <strong>debounced</strong> re-evaluation,
so streamed replies settle only after a quiet period — evaluating on every
token melts the main thread.</li>
<li>Wrap embedded code spans with <code>dir=ltr</code> + <code>unicode-bidi: embed</code> so
identifiers keep their shape inside RTL paragraphs.</li>
</ol>
