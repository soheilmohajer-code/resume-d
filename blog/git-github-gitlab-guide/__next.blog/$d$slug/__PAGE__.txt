24:T4ef8,<p>Before Docker, before Linux, the tool that changed how I work most
daily was Git. Every project I&#39;ve shipped — Android apps on Cafe Bazaar,
the <a href="https://github.com/soheilmohajer-code/parsichat-fixer">ParsiChat Fixer extension</a>,
even this website — lives in Git. And every time a friend asks me to teach
them programming, I watch them trip over the same confusion: mixing up
<strong>Git</strong> with <strong>GitHub</strong>. This post untangles it once and for all.</p>
<blockquote>
<p><strong>TL;DR</strong> — Git is the version-control <em>tool</em> that must be installed on
your computer (on Windows it comes with the <strong>Git Bash</strong> terminal).
GitHub and GitLab are <em>websites</em> that host your Git repositories online.
Learn the commands once, and both platforms speak the same language.</p>
</blockquote>
<h2 id="what-git-actually-is">What Git actually is</h2><p><strong>Git is a distributed version-control system</strong> — a tool that records
snapshots of your project (called <strong>commits</strong>) so you can revisit any
point in history, experiment on parallel timelines (called <strong>branches</strong>),
and merge work from many people without overwriting each other.</p>
<p>Think of it like a video-game save system for code:</p>
<ul>
<li><strong>Save points</strong> = commits. Made a mess? Load an earlier save.</li>
<li><strong>New game plus</strong> = branches. Try a risky idea on a side timeline
without touching the main story.</li>
<li><strong>Multiplayer</strong> = merging. Everyone plays, then the timelines combine.</li>
</ul>
<p>Two properties make Git special:</p>
<ol>
<li><strong>Distributed</strong> — everyone who clones a project has the <em>full history</em>
on their machine. No internet? You can commit, branch and browse
history offline. The server (GitHub/GitLab) is just where teams sync —
not the brain.</li>
<li><strong>Content-addressed</strong> — every snapshot gets a unique SHA-1 hash. If a
file changes, Git knows; nothing silently gets lost.</li>
</ol>

program that runs on your computer</strong> — and the website can&#39;t work without
it on your machine.</p>
<p><strong>Installing:</strong></p>
<ul>
<li><strong>Windows</strong> — download the installer from
<a href="https://git-scm.com">git-scm.com</a>. It installs Git <em>and</em> <strong>Git Bash</strong> —
a terminal that speaks Linux-style commands (<code>ls</code>, <code>cd</code>, <code>ssh</code>). Use Git
Bash rather than CMD or PowerShell: every Git tutorial on Earth assumes
this Linux-like shell, and tools like <code>ssh</code> come bundled.</li>
<li><strong>Linux</strong> — it&#39;s one command: <code>sudo apt install git</code> (Debian/Ubuntu).</li>
<li><strong>macOS</strong> — run <code>git --version</code> once; macOS offers to install it.</li>
</ul>

stamps every commit with it):</p>

</tbody></table>
<p>Key insight: <strong>both speak exactly the same Git.</strong> The <code>git push</code>, <code>git clone</code> and <code>git pull</code> you learn once work identically with either. The
differences are the website around it: GitLab&#39;s built-in CI/CD and
self-hosting make it the favorite of companies that want everything in
one place and under their own roof; GitHub&#39;s community makes it the
default for open source (and it&#39;s where my public projects live).</p>
<p>One repo can even push to both at once — teams commonly mirror GitHub to
GitLab for backup.</p>
<h2 id="the-core-workflow-the-90-you39ll-use-daily">The core workflow (the 90% you&#39;ll use daily)</h2><p>Git has three &quot;areas&quot; your files live in, and every command moves files
between them:</p>
<div class="term" dir="ltr"><div class="term-bar"><span class="d d1"></span><span class="d d2"></span><span class="d d3"></span><span class="file">snippet.txt</span><button type="button" class="copy" data-copy>COPY</button></div><pre class="shiki vitesse-dark" style="background-color:#121212;color:#dbd7caee" tabindex="0"><code><span class="line"><span>Working directory  →(git add)→  Staging area  →(git commit)→  Local repo  →(git push)→  Remote (GitHub/GitLab)</span></span></code></pre></div><div class="term" dir="ltr"><div class="term-bar"><span class="d d1"></span><span class="d d2"></span><span class="d d3"></span><span class="file">snippet.bash</span><button type="button" class="copy" data-copy>COPY</button></div><pre class="shiki vitesse-dark" style="background-color:#121212;color:#dbd7caee" tabindex="0"><code><span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> clone</span><span style="color:#C98A7D"> https://github.com/user/repo.git</span><span style="color:#758575DD">   # get a copy of a remote repo</span></span>
<span class="line"><span style="color:#B8A965">cd</span><span style="color:#C98A7D"> repo</span></span>
<span class="line"></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> status</span><span style="color:#758575DD">                # what changed? (use it constantly)</span></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> add</span><span style="color:#C98A7D"> index.html</span><span style="color:#758575DD">        # stage one file (or: git add . for everything)</span></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> commit</span><span style="color:#C99076"> -m</span><span style="color:#C98A7D77"> "</span><span style="color:#C98A7D">Add hero section</span><span style="color:#C98A7D77">"</span><span style="color:#758575DD">   # snapshot the staged changes</span></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> push</span><span style="color:#758575DD">                  # upload commits to the remote</span></span>
<span class="line"></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> pull</span><span style="color:#758575DD">                  # download + merge others' work</span></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> log</span><span style="color:#C99076"> --oneline</span><span style="color:#758575DD">         # browse history</span></span></code></pre></div><p>Commit often, write clear messages (&quot;Add hero section&quot;, not &quot;update&quot;),
and push at the end of a work session — that&#39;s the habit that makes
everything else easy.</p>
<h2 id="branches-and-pr-vs-mr">Branches, and PR vs MR</h2><p>A <strong>branch</strong> is a parallel timeline. The default one is <code>main</code> (or
<code>master</code> in older repos). You branch to build a feature without breaking
the working version:</p>
<div class="term" dir="ltr"><div class="term-bar"><span class="d d1"></span><span class="d d2"></span><span class="d d3"></span><span class="file">snippet.bash</span><button type="button" class="copy" data-copy>COPY</button></div><pre class="shiki vitesse-dark" style="background-color:#121212;color:#dbd7caee" tabindex="0"><code><span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> switch</span><span style="color:#C99076"> -c</span><span style="color:#C98A7D"> feature/login</span><span style="color:#758575DD">    # create + enter a new branch</span></span>
<span class="line"><span style="color:#758575DD"># ...work, commit, repeat...</span></span>
<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> push</span><span style="color:#C99076"> -u</span><span style="color:#C98A7D"> origin</span><span style="color:#C98A7D"> feature/login</span></span></code></pre></div><p>Then — on the website — you open a request to merge your branch back:</p>
<ul>
<li><svg class="brand-ico" viewBox="0 0 24 24" aria-hidden="true"><path fill="currentColor" d="M12 .297c-6.63 0-12 5.373-12 12 0 5.303 3.438 9.8 8.205 11.385.6.113.82-.258.82-.577 0-.285-.01-1.04-.015-2.04-3.338.724-4.042-1.61-4.042-1.61C4.422 18.07 3.633 17.7 3.633 17.7c-1.087-.744.084-.729.084-.729 1.205.084 1.838 1.236 1.838 1.236 1.07 1.835 2.809 1.305 3.495.998.108-.776.417-1.305.76-1.605-2.665-.3-5.466-1.332-5.466-5.93 0-1.31.465-2.38 1.235-3.22-.135-.303-.54-1.523.105-3.176 0 0 1.005-.322 3.3 1.23.96-.267 1.98-.399 3-.405 1.02.006 2.04.138 3 .405 2.28-1.552 3.285-1.23 3.285-1.23.645 1.653.24 2.873.12 3.176.765.84 1.23 1.91 1.23 3.22 0 4.61-2.805 5.625-5.475 5.92.42.36.81 1.096.81 2.22 0 1.606-.015 2.896-.015 3.286 0 .315.21.69.825.57C20.565 22.092 24 17.592 24 12.297c0-6.627-5.373-12-12-12"/></svg> GitHub calls it a <strong>Pull Request (PR)</strong></li>
<li><svg class="brand-ico" viewBox="0 0 24 24" aria-hidden="true"><path fill="currentColor" d="m23.6004 9.5927-.0337-.0862L20.3.9814a.851.851 0 0 0-.3362-.405.8748.8748 0 0 0-.9997.0539.8748.8748 0 0 0-.29.4399l-2.2055 6.748H7.5375l-2.2057-6.748a.8573.8573 0 0 0-.29-.4412.8748.8748 0 0 0-.9997-.0537.8585.8585 0 0 0-.3362.4049L.4332 9.5015l-.0325.0862a6.0657 6.0657 0 0 0 2.0119 7.0105l.0113.0087.03.0213 4.976 3.7264 2.462 1.8633 1.4995 1.1321a1.0085 1.0085 0 0 0 1.2197 0l1.4995-1.1321 2.4619-1.8633 5.006-3.7489.0125-.01a6.0682 6.0682 0 0 0 2.0094-7.003z"/></svg> GitLab calls it a <strong>Merge Request (MR)</strong></li>

<p>Same idea, different name: teammates review the code, CI runs your
tests, and only then does it land in <code>main</code>. In teams, <em>nothing</em> goes to
<code>main</code> directly — everything arrives through PRs/MRs.</p>

<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> clone</span><span style="color:#CB7676"> &#x3C;</span><span style="color:#C98A7D">ur</span><span style="color:#DBD7CAEE">l</span><span style="color:#CB7676">></span><span style="color:#758575DD">                   # copy a remote repo</span></span>

<span class="line"><span style="color:#80A665">git</span><span style="color:#C98A7D"> switch</span><span style="color:#C99076"> -c</span><span style="color:#C98A7D"> new-branch</span><span style="color:#758575DD">          # new branch</span></span>
